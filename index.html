Closer — working name

A neutral last-mile closure loop for timing and DRC ECOs.

Pre-alpha. There are no results here.
No benchmark has been run. There are no customers, no pilots, and no performance claims. If you are reading this to evaluate performance, stop: there is nothing to evaluate yet.

The question

Most of PPA optimisation is automated. The last stretch — post-route timing, DRC and congestion cleanup — is still expert manual work, and it is where tapeouts slip. The question this project tests is narrow:

Given a routed netlist that fails timing or DRC, which function-preserving edit sequence closes the most violation per unit of compute — and can the choice be learned cheaply enough to beat a tuned baseline, reproducibly?

What is being built

  • A harness that parses timing and DRC reports and records every experiment.
  • A library of edits that cannot change logic function by construction.
  • A structural audit between netlists (a stand-in, not formal equivalence).
  • An append-only audit trail, so every change is attributable and reversible.
  • Open-source flows first (OpenROAD); commercial tools only later, on a customer's licenses.

How a result will be claimed

The methodology is written before any run: fixed designs, fixed tool versions and image digests, three seeds, published compute budgets, a tuned baseline as the comparison, and the limitations stated up front. If the loop does not beat a tuned baseline, that gets published too.
